# Modul 7: TLS, Custom Certificate Authorities & Mutual TLS (mTLS)

## 1. Lernziele

Nach Abschluss dieses Moduls kannst du:
1. Zwischen **Server-Vertrauen** (Custom CA / Truststore) und **Client-Identität** (Client-Zertifikat + privater Schlüssel / Keystore) präzise **unterscheiden**.
2. TLS-Vertrauensfehler sauber über eine eigene **Custom CA** (`--cacert`) statt des Anti-Patterns `curl -k` / `--insecure` **beheben**.
3. **Mutual TLS (mTLS)** konsistent in `curl`, Bruno (GUI sowie CLI mit `--client-cert-config`) und SoapUI Open Source **einrichten**.
4. Einen fehlgeschlagenen mTLS-Handshake ohne gültiges Client-Zertifikat auf TLS-/HTTP-Ebene sicher **diagnostizieren**.

## 2. Architektur und Kernkonzepte

Im lokalen Labor terminiert `tls-proxy` (`nginx`) zwei getrennte HTTPS-Ports vor `go-httpbin`:
- **`https://localhost:8444` (Custom-CA Server-TLS):** Nur der Client prüft das Server-Zertifikat gegen `lab/certs/out/ca.crt`.
- **`https://localhost:8443` (Striktes mTLS):** Zusätzlich verlangt der Server (`ssl_verify_client on`) ein von derselben Root-CA signiertes Client-Zertifikat (`client.crt` + `client.key` bzw. `client.pfx`) und reicht den Distinguished Name im Header `X-Client-Cert-DN` ans Backend weiter.

**Anti-Pattern `curl -k` (`--insecure`):** Das Abschalten der Zertifikatsprüfung öffnet Man-in-the-Middle-Angriffen Tür und Tor und verdeckt abgelaufene oder falsch ausgestellte SAN-Zertifikate bis zum Produktivgang.

### Vergleichstabelle: TLS & mTLS über alle drei Werkzeuge

| Aspekt | `curl` | Bruno (GUI v4.1+ & CLI) | SoapUI Open Source 5.10.1 |
| :--- | :--- | :--- | :--- |
| **Custom CA (Server-Trust)** | `--cacert lab/certs/out/ca.crt` | GUI: *Preferences → General → Custom CA*; CLI: `--cacert` | Java Truststore (`lab-truststore.jks`) in *Preferences → SSL Settings* |
| **Client-Zertifikat (mTLS)** | `--cert client.crt --key client.key` (oder PFX) | GUI: *Collection Settings → Client Certificates* (relative Pfade); CLI: **`--client-cert-config`** | Keystore (`client-keystore.jks`) in *SSL Settings* oder Projekt-Keystore |
| **Wichtiger CI-Fallstrick** | Pfad zur CA & Key-Datei relativ/absolut prüfen | **Bruno CLI liest keine globalen GUI-Preferences!** Immer `--cacert` & `--client-cert-config` übergeben | SoapUI-TestRunner nutzt JVM-Truststore/Projekt-Keystore |

## 3. Geführter Walkthrough (`curl`, `Bruno`, `SoapUI`)

### `curl` (Custom CA & mTLS)

```bash
# 1. Server-TLS ohne --cacert schlaegt fehl (SSL certificate problem: self-signed certificate in chain)
curl -i https://localhost:8444/headers || true

# 2. Sauberes Server-Trust via --cacert (Port 8444 -> 200 OK)
curl -sS --cacert lab/certs/out/ca.crt https://localhost:8444/headers | jq '.headers."X-Tls-Mode"'

# 3. Striktes mTLS ohne Client-Cert (Port 8443 -> HTTP 400 Bad Request: No required SSL certificate was sent)
curl -i --cacert lab/certs/out/ca.crt https://localhost:8443/headers

# 4. Vollstaendiger mTLS-Handshake mit Client-Cert + Key (Port 8443 -> 200 OK)
curl -sS --cacert lab/certs/out/ca.crt \
  --cert lab/certs/out/client.crt \
  --key lab/certs/out/client.key \
  https://localhost:8443/headers | jq '.headers | {"X-Tls-Mode", "X-Client-Cert-Verify", "X-Client-Cert-Dn"}'
```

### `Bruno` (GUI & CLI `--client-cert-config`)

1. **GUI:** Hinterlege `lab/certs/out/ca.crt` unter *Preferences → General → Custom CA Certificate*. Für mTLS trage unter *Collection Settings → Client Certificates* die Domain `localhost` mit `client.crt` und `client.key` (oder `client.pfx` + Passwort `{{certPass}}`) ein. Bei gleicher Domain haben aktivierte Collection-Zertifikate Vorrang vor globalen Zertifikaten.
2. **CLI / CI-Pipeline:** Kopiere `client-cert-config.example.json` nach `client-cert-config.json` (in `.gitignore`!) und achte zwingend auf `"enabled": true`:
   ```bash
   cp collections/bruno/auth-hygiene-lab/client-cert-config.example.json \
      collections/bruno/auth-hygiene-lab/client-cert-config.json
   cd collections/bruno/auth-hygiene-lab
   bru run tls-mtls --env local \
     --cacert ../../../lab/certs/out/ca.crt \
     --client-cert-config ./client-cert-config.json
   ```

### `SoapUI Open Source 5.10.1`

1. Öffne *File → Preferences → SSL Settings*:
   - **KeyStore:** `lab/certs/out/client-keystore.jks`, Passwort `CHANGE_ME_LAB_ONLY` (oder aus `lab/.env`).
   - **Requires Client Authentication** anhaken.
2. Alternativ für eigene Trust-Konfiguration: `lab/certs/out/lab-truststore.jks` über Java VM Options (`-Djavax.net.ssl.trustStore=...`) einbinden und einen REST-Request gegen `https://localhost:8443/headers` senden.

## 4. Typische Fallstricke und Troubleshooting

| Fehlerbild | Ursache | Diagnose & Lösung |
| :--- | :--- | :--- |
| mTLS funktioniert in Bruno GUI, schlägt aber in `bru run` fehl | Bruno CLI liest keine globalen GUI-Preferences; oder `"enabled": true` fehlt in `client-cert-config.json` | `--cacert` und `--client-cert-config` explizit angeben; `"enabled": true` prüfen |
| `curl: (60) SSL certificate problem` | Lokale Root-CA wurde nicht übergeben, oder Server-Zertifikat besitzt keinen passenden SAN (`localhost`) | `--cacert lab/certs/out/ca.crt` nutzen; SAN via `openssl x509 -in server.crt -noout -text` prüfen |
| Port `8443` antwortet mit `400 No required SSL certificate was sent` | Client hat kein Zertifikat gesendet oder Domain-Filter in `client-cert-config.json` passt nicht | `domain` in Config prüfen (`localhost`), Pfad zu `client.crt`/`client.key` verifizieren |
| `openssl` / `keytool` meldet falsches Passwort bei `.pfx` / `.jks` | `LAB_CERT_PASSWORD` stimmt nicht überein | Zertifikate über `./lab/certs/generate-certs.sh` mit definiertem `LAB_CERT_PASSWORD` neu erzeugen |

## 5. Spickzettel (Cheat Sheet)

| Befehl / Konfiguration | Wirkung |
| :--- | :--- |
| `curl --cacert ca.crt https://localhost:8444/...` | Prüft Server-Zertifikat gegen lokale Root-CA |
| `curl --cacert ca.crt --cert client.crt --key client.key` | Authentifiziert Client per mTLS |
| `openssl x509 -in server.crt -noout -text` | Prüft Aussteller, Laufzeit und Subject Alternative Names (SAN) |
| `bru run -r --cacert ... --client-cert-config ...` | CI-sicherer mTLS-Lauf in Bruno CLI |
| `"enabled": true` | Pflichtfeld auf Top-Level in `client-cert-config.json` |
