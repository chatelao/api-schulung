# Modul 5: Klassische Credentials & Secret-Hygiene

## 1. Lernziele

Nach Abschluss dieses Moduls kannst du:
1. Die Funktionsweise und Sicherheitsgrenzen von **HTTP Basic**, **HTTP Digest**, statischen **API-Keys** und **Bearer Tokens** sauber **erklären**.
2. Geheimnisse in `curl` konsequent vor Shell-Historie und Prozesslisten schützen (`-K -`, `--netrc-file`, `--oauth2-bearer`, Umgebungsvariablen).
3. Geheimnisse in Bruno sauber über `secret: true` in `environments/*.yml` oder per `.gitignore` ausgeschlossene `.env`-Dateien **kapseln**.
4. Ein Repository per `git status` und Grep-Audit verlässlich auf versehentliche Secret-Leaks **prüfen**.

## 2. Architektur und Kernkonzepte

Klassische Authentifizierungsverfahren sind technisch simpel, führen in der Praxis aber häufig zu schwerwiegenden Secret-Leaks in Git-Commits, `~/.bash_history`, CI-Logs oder Proxy-Access-Logs.

**Kardinalregel zu Base64:** `Authorization: Basic <base64(user:pass)>` ist **keine Verschlüsselung**, sondern eine triviale Kodierung! Basic Auth und statische API-Keys/Bearer-Tokens sind daher **ausschliesslich über HTTPS/TLS** zulässig. Ebenso dürfen API-Keys oder Tokens **niemals in URL-Query-Parametern** (`?api_key=...` oder `?access_token=...`) übergeben werden, da URLs unverschlüsselt in Server-Logs, Browser-Historien und `Referer`-Headern landen.

### Vergleichstabelle: Klassische Authentifizierungsverfahren & Secret-Speicherung

| Verfahren | Übertragung | Schutz bei Klartext-HTTP | Secret-Schutz in `curl` | Secret-Schutz in Bruno |
| :--- | :--- | :--- | :--- | :--- |
| **HTTP Basic** | Header `Authorization: Basic ...` | **Keiner** (nur Base64!) | `-K -` (`stdin`) oder `--netrc-file` | `secret: true` im Environment / `.env` |
| **HTTP Digest** | Challenge-Response (`Nonce` + Hash) | Passwort nicht im Klartext, aber anfällig für Downgrade/MITM | `--digest -K -` | `auth: type: digest` + `secret: true` |
| **API-Key (Header)** | z. B. `X-Api-Key: ...` | **Keiner** (Klartext im Header) | `-H @-` / `-K -` / Env-Var | `auth: type: apikey` (`placement: header`) |
| **Bearer Token** | Header `Authorization: Bearer ...` | **Keiner** (Besitz = Zugriff) | `-H` aus `-K -` oder `--oauth2-bearer` via Env | `auth: type: bearer` + `secret: true` |

## 3. Geführter Walkthrough (`curl`, `Bruno`, `SoapUI`)

### `curl`: Keine Secrets in der Kommandozeile!

Schlechtes Beispiel (erscheint in `ps aux` und `~/.bash_history`):
`curl -u user:geheim http://localhost:8180/basic-auth/user/geheim`

**Sichere Alternative 1: `--config -` (`-K -`) über `stdin`:**

```bash
curl -sS --fail-with-body -K - "http://localhost:8180/basic-auth/labuser/${HTTPBIN_BASIC_PASS}" <<EOF
user = "labuser:${HTTPBIN_BASIC_PASS}"
EOF
```

**Sichere Alternative 2: `--netrc-file` (Datei mit `chmod 600`, in `.gitignore`!):**

```bash
cat > /tmp/lab.netrc <<EOF
machine localhost login labuser password ${HTTPBIN_BASIC_PASS}
EOF
chmod 600 /tmp/lab.netrc
curl -sS --fail-with-body --netrc-file /tmp/lab.netrc \
  "http://localhost:8180/basic-auth/labuser/${HTTPBIN_BASIC_PASS}"
rm -f /tmp/lab.netrc
```

**Sichere Alternative 3: `--oauth2-bearer` oder Header per `-K -`:**

```bash
curl -sS --fail-with-body -K - "http://localhost:8180/bearer" <<EOF
oauth2-bearer = "${HTTPBIN_BEARER_TOKEN}"
EOF
```

### `Bruno` (OpenCollection YAML)

Öffne [collections/bruno/auth-hygiene-lab/](https://github.com/chatelao/api-schulung/blob/main/collections/bruno/auth-hygiene-lab/opencollection.yml):
1. In `environments/local.yml` sind Geheimnisse mit `secret: true` und leerem `value: ""` deklariert:
   ```yaml
   - name: apiKey
     value: ""
     secret: true
   ```
   Die Werte werden in Bruno Desktop lokal verschlüsselt gespeichert — **niemals** in Git.
2. Für die CLI (`bru run`) oder `.env`-Nutzung existiert eine `.env.example`, aus der lokal eine per `.gitignore` ausgeschlossene `.env` kopiert wird (`{{$processEnv.HTTPBIN_API_KEY}}`).
3. Zusätzlich unterstützt Bruno v4 externe Secret Manager (HashiCorp Vault, AWS Secrets Manager, Azure Key Vault) über `--secrets-env-file`.

### `SoapUI Open Source 5.10.1`

In SoapUI werden Basic-Credentials im Request-Panel über den Tab **Auth (Basic)** oder globale Projekt-Properties (`${#Project#apiKey}`) übergeben, die vor einem Git-Commit aus der Projekt-XML entfernt bzw. per Kommandozeilen-Override injiziert werden.

## 4. Typische Fallstricke und Troubleshooting

| Fehlerbild | Ursache | Diagnose & Lösung |
| :--- | :--- | :--- |
| `bru run` schlägt bei `secret: true`-Variablen mit `401` fehl | Bruno CLI liest keine verschlüsselten Desktop-App-Secrets | Werte per `--env-var "apiKey=..."` übergeben oder `{{$processEnv.VAR}}` + `.env` nutzen |
| `.env` taucht in `git status` auf | `.env` wurde vor `.gitignore` angelegt oder `.gitignore` fehlt im Unterordner | `git check-ignore -v <pfad/.env>` prüfen; ggf. `git rm --cached` ausführen |
| `curl --digest` liefert zweimal `401` | Bei Digest Auth ist der erste `401` (mit `WWW-Authenticate: Digest nonce=...`) normal, erst der zweite Request sendet den Hash | `curl -v` ausführen; auf zweiten Request achten und Benutzername/Passwort prüfen |
| Secret erscheint in CI-Logs (JUnit/JSON-Report) | `bru run` protokolliert Standard-Header in Reports | `--reporter-skip-headers Authorization X-Api-Key` bzw. `--reporter-skip-all-headers` setzen |

## 5. Spickzettel (Cheat Sheet)

| Werkzeug / Flag | Zweck |
| :--- | :--- |
| `curl -K -` | Liest sensible Optionen (`user`, `header`, `oauth2-bearer`) sicher von `stdin` |
| `curl --netrc-file <file>` | Lädt Host/Login/Passwort aus einer `chmod 600`-Datei |
| `curl --digest` | Aktiviert HTTP Digest Challenge-Response |
| `secret: true` (Bruno YAML) | Verhindert das Schreiben des Secret-Werts in `environments/*.yml` |
| `git check-ignore -q .env` | Verifiziert programmatisch, dass `.env` von Git ignoriert wird |
