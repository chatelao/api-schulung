# Modul 10: OAuth-Praxis mit Keycloak in Bruno Desktop und SoapUI

## 1. Lernziele

Nach Abschluss dieses Moduls kannst du:
1. Den **Authorization Code Flow + PKCE (`S256`)** über den System-Browser in **Bruno Desktop** einrichten und Token-Vererbung auf Collection-/Ordner-/Request-Ebene (`{{$oauth2.<tokenId>.access_token}}`) **konfigurieren**.
2. Automatische Token-Erneuerung und `401`-Recovery über `bru.getOauth2CredentialVar()` und `bru.resetOauth2Credential(credentialId)` in Bruno **nachvollziehen**.
3. Den **Client-Credentials-Flow** (Maschine-zu-Maschine / M2M) headless im Bruno Collection Runner ausführen.
4. Eine ehrliche OAuth-Kontrastkonfiguration in **SoapUI Open Source 5.10.1** (Bearer im Header, niemals in der URL) einrichten und die Grenzen zu **ReadyAPI** sauber **benennen**.

## 2. Architektur und Kernkonzepte

In der Praxis unterscheiden wir zwei OAuth-2.1-Anwendungsfälle:
- **Benutzer-Login (Authorization Code + PKCE):** Eine App handelt im Namen von `alice` oder `bob-admin`. Bruno öffnet hierfür den **System-Browser**, du meldest dich bei Keycloak an, und Bruno holt automatisch das Access Token ab.
- **Maschine-zu-Maschine (Client Credentials):** Zwei Server sprechen direkt miteinander (z. B. `m2m-service-client` ohne menschlichen Benutzer).

### Vergleichstabelle: OAuth-2-Fähigkeiten in Bruno Desktop vs. SoapUI OS 5.10.1

| Merkmal | Bruno Desktop (OpenCollection YAML) | SoapUI Open Source 5.10.1 |
| :--- | :--- | :--- |
| **Authorization Code + PKCE (`S256`)** | **Voll unterstützt** (System-Browser, `PKCE`, Auto-Fetch/Refresh) | **Nicht dokumentiert / limitiert** (automatisierte Browser-OAuth-Skripte nur in **ReadyAPI**) |
| **Client Credentials (M2M)** | Nativ in Collection/Request (`grantType: client_credentials`) | Nativ über OAuth-2-Profil (`Client Credentials`) |
| **Token-Vererbung** | `auth: inherit` oder `{{$oauth2.<id>.access_token}}` | OAuth-2-Profil pro Request; **immer** `Header` statt Query-String wählen! |

## 3. Geführter Walkthrough (`Bruno Desktop` & `SoapUI`)

### `Bruno Desktop`: Drei vorbereitete Collections

1. **Authorization Code + PKCE (`collections/bruno/oauth-pkce-lab/`):**
   - Öffne die Collection in Bruno Desktop und wähle Environment **`local`**.
   - Öffne die Collection-Einstellungen → Tab **Auth**: Dort ist OAuth 2.0 (`Authorization Code`, **PKCE aktiviert**, Client `bruno-pkce-client`, Token ID `keycloakPkce`) hinterlegt.
   - Klicke auf **Get Access Token**: Dein Browser öffnet das Keycloak-Login-Fenster (`http://localhost:8081`). Melde dich mit `alice` / `CHANGE_ME_LAB_USER_PASS` an.
   - Führe alle drei Requests aus:
     - `01-user_info_coll-auth`: Erbt das Token direkt von der Collection (`Inherit`).
     - `02-user_info_request-auth`: Überschreibt die OAuth-Konfiguration lokal am Request.
     - `03-user_info_custom`: Nutzt `{{$oauth2.keycloakPkce.access_token}}` bzw. Skript-Zugriff inklusive automatischem Reset (`bru.resetOauth2Credential`) bei `401`.

2. **Client Credentials M2M (`collections/bruno/oauth-client-credentials-lab/`):**
   - Öffne das Environment `local`, trage in das Secret-Feld `clientSecret` den Laborwert `CHANGE_ME_LAB_M2M_SECRET` ein und führe `01-call-bearer-m2m` und `02-introspect-m2m-token` aus (ganz ohne Browser-Fenster!).

3. **Legacy ROPC Audit (`collections/bruno/oauth-legacy-ropc-audit/`):**
   - **WARNUNG (Legacy-Negativbeispiel):** Zeigt den veralteten `password`-Grant gegen `legacy-ropc-audit-client` ausschliesslich zu Audit-/Migrationszwecken — niemals in neuen Systemen verwenden!

### `SoapUI Open Source 5.10.1`: Kontrast-Konfiguration

Öffne [oauth-contrast-soapui-project.xml](https://github.com/chatelao/api-schulung/blob/main/collections/soapui/oauth-contrast-soapui-project.xml):
- Im Tab **Auth → OAuth 2.0 (`KeycloakM2M`)**:
  - **Access Token Position:** Zwingend **`Header`** (`Authorization: Bearer ...`) — **niemals** `Query String`!
  - Für interaktives PKCE bleibt Bruno/Browser führend, weil SoapUI Open Source keinen automatisierten PKCE-Browser-Flow bietet.

> **Für Fortgeschrittene (Shell & `curl`):** Wie man M2M-Tokens ohne Secret-Leakage über `curl -K -` abruft, zeigt [Advanced A05](../advanced/A05.md).

## 4. Typische Fallstricke und Troubleshooting

| Fehlerbild | Ursache | Diagnose & Lösung |
| :--- | :--- | :--- |
| Browser-Login in Bruno öffnet Callback nicht | Redirect-URI in Bruno stimmt nicht exakt mit `bruno-pkce-client` in Keycloak überein | In Keycloak registriert: `https://oauth.usebruno.com/callback`, `http://localhost:8080/callback`, `http://localhost:12345/callback` |
| `401 invalid_client` bei Client Credentials | Secret `clientSecret` (`CHANGE_ME_LAB_M2M_SECRET`) wurde im Environment `local` noch nicht eingetragen | In Bruno Desktop unter *Environments → local* eintragen |
| SoapUI sendet `?access_token=...` in der URL | Token-Position steht noch auf *Query String* | Im OAuth-2-Profil auf **Header** umstellen |

## 5. Spickzettel (Cheat Sheet)

| Konstrukt | Bedeutung |
| :--- | :--- |
| `{{$oauth2.keycloakPkce.access_token}}` | Greift auf das aktuell in Bruno gespeicherte OAuth-Token zu |
| `bru.resetOauth2Credential("keycloakPkce")` | Verwirft ein abgelaufenes Token, damit beim nächsten Aufruf neu geholt wird |
| `grantType: client_credentials` | M2M-Flow ohne Benutzerinteraktion |
| `Access Token Position: Header` | Einzig sichere Übertragung in SoapUI & Bruno (niemals Query String!) |
