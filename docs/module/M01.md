# Modul 1: HTTP-Fundament & `curl` ohne Magie

## 1. Lernziele

Nach Abschluss dieses Moduls kannst du:
1. Den Aufbau einer HTTP-Nachricht (Request-Line, Header, Leerzeile, Body) und die Statuscode-Klassen `2xx` bis `5xx` anhand realer Traces **analysieren**.
2. Idempotente HTTP-Verben (`GET`, `PUT`, `DELETE`) von nicht-idempotenten Operationen (`POST`, `PATCH`) sicher **unterscheiden**.
3. Content Negotiation über `Accept` und `Content-Type` gezielt **steuern** und Diagnoseausgaben mit `curl -v` auswerten.
4. JSON-Payloads sauber mit `curl --json` senden und Antworten automatisiert mit `jq` **extrahieren**.

## 2. Architektur und Kernkonzepte

HTTP ist ein zustandsloses Client-Server-Protokoll auf Text- (HTTP/1.1) bzw. Binär-Frame-Basis (HTTP/2). Jeder Austausch besteht aus einem **Request** (`Methode Pfad Version`, Header, optionaler Body) und einer **Response** (`Version Statuscode Reason-Phrase`, Header, optionaler Body).

Ein zentrales Architekturprinzip robuster APIs ist **Idempotenz**: Ein Request ist idempotent, wenn mehrfaches identisches Ausführen denselben Serverzustand hinterlässt wie einmaliges Ausführen. Das ist entscheidend für automatische Retries nach Netzwerkabbrüchen.

### Vergleichstabelle: HTTP-Verben & Semantik

| HTTP-Verb | Zweck | Request-Body | Sicher (*Safe*) | Idempotent | Typischer Erfolgs-Code |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `GET` | Ressource lesen | Nein | Ja | Ja | `200 OK` |
| `POST` | Neue Ressource anlegen / Aktion auslösen | Ja | Nein | **Nein** | `201 Created` / `200 OK` |
| `PUT` | Ressource vollständig ersetzen | Ja | Nein | Ja | `200 OK` / `204 No Content` |
| `PATCH` | Ressource partiell aktualisieren | Ja | Nein | Nein (meist) | `200 OK` |
| `DELETE` | Ressource entfernen | Optional | Nein | Ja | `200 OK` / `204 No Content` |

### Statuscode-Klassen im Überblick

- **`2xx` Erfolg:** `200 OK`, `201 Created` (mit `Location`-Header), `204 No Content`.
- **`3xx` Weiterleitung:** `301 Moved Permanently`, `302 Found`, `307`/`308` (behalten HTTP-Methode bei).
- **`4xx` Client-Fehler:** `400 Bad Request` (Syntax/Schema), `401 Unauthorized` (Authentifizierung fehlt/ungültig), `403 Forbidden` (Berechtigung fehlt), `404 Not Found`, `405 Method Not Allowed`, `415 Unsupported Media Type` (`Content-Type` falsch).
- **`5xx` Server-Fehler:** `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`.

## 3. Geführter Walkthrough (`curl` + `jq`)

> **Hinweis:** In M01 arbeiten wir bewusst pur mit `curl` und `jq`, um die Transport- und Protokollebene ohne GUI-Abstraktion zu beherrschen. Ab M02 und M03 triangulieren wir mit **Bruno** und **SoapUI**.

### Schritt 1: HTTP-Header und Weiterleitungen mit `go-httpbin` inspizieren

```bash
# Vollstaendigen Request/Response-Handshake inklusive Header anzeigen
curl -v http://localhost:8180/headers

# Weiterleitung beobachten (ohne -L gibt es nur 302, mit -L folgt curl dem Location-Header)
curl -i http://localhost:8180/redirect/2
curl -iL http://localhost:8180/redirect/2
```

### Schritt 2: Content Negotiation & Fehlercodes gezielt provozieren

```bash
# 415 Unsupported Media Type provozieren (Text statt JSON an Petstore)
curl -i -X POST http://localhost:8080/api/v3/pet \
  -H "Content-Type: text/plain" \
  -d '{"id": 1001, "name": "Bello"}'

# 405 Method Not Allowed provozieren (DELETE ohne ID auf Collection-Pfad)
curl -i -X DELETE http://localhost:8080/api/v3/pet
```

### Schritt 3: Sauberes JSON-POST mit `--json` und `jq`-Extraktion

Seit `curl 7.82.0` setzt das Flag `--json` automatisch `Content-Type: application/json`, `Accept: application/json` und sendet den Body als POST-Payload.

```bash
# Ressource anlegen und ID mit jq extrahieren
CREATED_ID=$(curl -sS --fail-with-body --json '{
  "id": 1001,
  "name": "Bello",
  "status": "available"
}' http://localhost:8080/api/v3/pet | jq -r '.id')

echo "Angelegte Pet-ID: ${CREATED_ID}"

# Ressource erneut abrufen und Status pruefen
curl -sS -H "Accept: application/json" \
  "http://localhost:8080/api/v3/pet/${CREATED_ID}" | jq '{id, name, status}'

# Ressource sauber loeschen
curl -i -X DELETE "http://localhost:8080/api/v3/pet/${CREATED_ID}"
```

### Schritt 4: `-d` vs. `--data-binary` verstehen

Das Standard-Flag `-d` / `--data` entfernt Zeilenumbrüche (`\r` und `\n`) aus Dateien! Für strukturierte Payloads (insbesondere XML, SOAP oder exakte JSON-Hashes) muss immer `--data-binary @datei` verwendet werden, um die Byte-Integrität zu wahren.

## 4. Typische Fallstricke und Troubleshooting

| Fehlerbild | Ursache | Diagnose & Lösung |
| :--- | :--- | :--- |
| Server antwortet mit `415 Unsupported Media Type` | Fehlendes oder falsches `Content-Type`-Header-Feld (Standard bei `curl -d` ist `application/x-www-form-urlencoded`) | Mit `curl -v` gesendete Request-Header prüfen; `--json` oder `-H "Content-Type: application/json"` setzen |
| `curl` bricht bei `404`/`500` im Bash-Skript nicht ab | Standardmässig gibt `curl` auch bei HTTP `4xx`/`5xx` Exit-Code `0` zurück | `--fail-with-body` (ab curl 7.76) oder `-f` verwenden, damit Skripte sauber abbrechen |
| `curl` zeigt bei Redirects scheinbar leeren Body | Status `302 Found` liefert `Location`-Header ohne automatisches Folgen | Flag `-L` (`--location`) ergänzen; bei `POST` auf `301`/`302` Vorsicht vor Methodenwechsel auf `GET` |
| Zeilenumbrüche verschwinden bei Datei-Upload | `-d @payload.txt` strippt `\n`/`\r` | Immer `--data-binary @payload.txt` verwenden |

## 5. Spickzettel (Cheat Sheet)

| Flag / Werkzeug | Wirkung |
| :--- | :--- |
| `curl -v <url>` | Zeigt TLS-Handshake, Request-Header (`>`) und Response-Header (`<`) |
| `curl -i <url>` | Gibt Response-Header vor dem Body aus |
| `curl -sS` | Silent-Modus ohne Fortschrittsbalken, zeigt aber Fehler an |
| `curl --fail-with-body` | Exit-Code != 0 bei HTTP >= 400, gibt Fehler-Body dennoch aus |
| `curl -L` | Folgt HTTP-`Location`-Weiterleitungen automatisch |
| `curl --json '{...}'` | Sendet JSON mit `Content-Type` und `Accept: application/json` |
| `curl --data-binary @file` | Sendet Datei bytegenau ohne Entfernung von Zeilenumbrüchen |
| `jq -r '.id'` | Extrahiert ein JSON-Feld ohne Anführungszeichen (`raw`) |
