# Musterlösung M11: OpenID Connect (OIDC)

## Lösung Aufgabe A: Discovery & JWKS
- Keycloak Discovery liefert `issuer: http://localhost:8081/realms/api-lab` und `jwks_uri: http://localhost:8081/realms/api-lab/protocol/openid-connect/certs`.
- Unter `jwks_uri` liegt der öffentliche Signatur-Schlüssel (`"use": "sig"`, `"kty": "RSA"`, `"alg": "RS256"`), identifiziert durch seine eindeutige `kid`.

## Lösung Aufgabe B: Kontrast ID Token vs. Access Token
1. **Zielgruppe (`aud`):** ID Token enthält `bruno-pkce-client`; Access Token enthält `api-lab-orders` (und `account`).
2. **Typ (`typ`):** ID Token = `"ID"`, Access Token = `"Bearer"`.
3. **Berechtigungen:** Nur das Access Token enthält `scope` und `realm_access.roles`.
4. **Verwendung:** `/userinfo` und Fach-APIs akzeptieren ausschliesslich das Access Token (`200 OK`).

## Lösung Aufgabe C & Bonus D
- In OpenAPI 3.1 verweist `type: openIdConnect` über `openIdConnectUrl` direkt auf `/.well-known/openid-configuration`.
- Base64URL-Dekodierung macht den JSON-Inhalt nur lesbar — wird ein Zeichen im Payload verändert, passt die RSA-Signatur nicht mehr zum öffentlichen Schlüssel aus `jwks_uri`, und der Server weist das Token mit `401` ab.

*(Für die Shell-/`curl`-Variante siehe [Advanced A05](../advanced/A05.md).)*
