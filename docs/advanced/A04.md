# A04: TLS, OpenSSL-Zertifikatsprüfung & Mutual TLS (mTLS) per `curl`

Statt TLS-Vertrauensfehler mit dem gefährlichen Flag `-k` / `--insecure` abzuschalten, verankern wir im Terminal immer explizit die interne Root-CA (`--cacert`).

## 1. Zertifikate mit `openssl` inspizieren

```bash
openssl x509 -in lab/certs/out/server.crt -noout -subject -issuer -ext subjectAltName
openssl x509 -in lab/certs/out/client.crt -noout -subject -issuer
```

## 2. Custom-CA TLS (`8444`) & Striktes mTLS (`8443`) per `curl`

```bash
# 1. Server-TLS mit lokaler Custom CA (Port 8444 -> 200 OK)
curl -sS --cacert lab/certs/out/ca.crt https://localhost:8444/headers | jq '.headers."X-Tls-Mode"'

# 2. Negativtest auf mTLS-Port 8443 ohne Client-Zertifikat -> HTTP 400
curl -i --cacert lab/certs/out/ca.crt https://localhost:8443/headers

# 3. Vollstaendiger mTLS-Handshake mit Client-Zertifikat + Key (Port 8443 -> 200 OK)
curl -sS --cacert lab/certs/out/ca.crt \
  --cert lab/certs/out/client.crt \
  --key lab/certs/out/client.key \
  https://localhost:8443/headers | jq '.headers | {"X-Tls-Mode", "X-Client-Cert-Verify", "X-Client-Cert-Dn"}'

# 4. PKCS#12 (.pfx) sicher via -K - verwenden
curl -sS --cacert lab/certs/out/ca.crt -K - https://localhost:8443/headers <<'EOF' | jq '.headers."X-Client-Cert-Verify"'
cert-type = "P12"
cert = "lab/certs/out/client.pfx:CHANGE_ME_LAB_ONLY"
EOF
```
