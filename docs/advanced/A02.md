# A02: SOAP 1.1/1.2 & bytegenauer XML-Versand (`--data-binary`)

Beim Versand von XML/SOAP über `curl` lauert ein klassischer Fallstrick: `-d @datei.xml` entfernt Zeilenumbrüche (`\n` / `\r`), was XML-Parser und spätere WS-Security-Signaturen zerstört. Deshalb gilt für XML/SOAP immer **`--data-binary @datei.xml`**.

## 1. Praxis-Walkthrough (SOAP 1.1 vs. SOAP 1.2)

```bash
# 1. WSDL abrufen
curl -sS "http://localhost:9000/soap?wsdl" | head -n 25

# 2. SOAP 1.1 Request (text/xml + SOAPAction-Header Pflicht!)
curl -i -X POST "http://localhost:9000/soap" \
  -H "Content-Type: text/xml; charset=utf-8" \
  -H 'SOAPAction: "http://api-schulung.local/orders/v1/CreateOrder"' \
  --data-binary @01-module/M03-soap-wsdl-soapui-curl/beispiel-payloads/create-order-soap11.xml

# 3. SOAP 1.2 Request (application/soap+xml, kein separater SOAPAction-Header)
curl -i -X POST "http://localhost:9000/soap" \
  -H "Content-Type: application/soap+xml; charset=utf-8" \
  --data-binary @01-module/M03-soap-wsdl-soapui-curl/beispiel-payloads/create-order-soap12.xml

# 4. Automatisiertes Referenzskript inkl. provoziertem XSD-Fault
./scripts/curl/m03-soap-call.sh
```

## 2. Ausblick: WSDL-Import über Bruno CLI

```bash
bru import wsdl --source http://localhost:9000/soap?wsdl --output /tmp/soap-bruno-check
```

Bruno erzeugt daraus eine OpenCollection-YAML-Collection mit XML-Templates; für WSDL-Schema-Validierung, WS-I Compliance und WS-Security bleibt SoapUI Open Source 5.10.1 jedoch überlegen.
